# Cycle 계획

> **Cycle 순서와 나누는 방식은 [확정] (2026-09-28 사용자 확인). 각 Cycle의 범위는 결정 사항이 아니다.**
> - 설계 초안(`reference-design.md`)의 "7. 개발 Cycle"을 작은 조각으로 다시 나눈 것이다.
> - 실제 범위는 각 Cycle의 `/cycle-start`에서 정하고 `docs/cycles/NN-<slug>/scope.md`에 쓴다. 앞 Cycle 결과를 보고 순서나 범위가 바뀌면 이 문서를 고친다.
> - 멀리 있는 Cycle일수록 거칠게 적었다. Cycle 05 이후는 그때 다시 나눈다.

## 나누는 기준 [확정: 2026-09-28]

- 한 Cycle은 "동작하는 결과물" 하나로 끝낸다 (원안 7장)
- 원안 Cycle 1은 관리자 화면, 수집 어댑터 2개, 중복 묶기, 캘린더를 한 번에 담고 있어서 세 개(01~03)로 나눴다. 순서는 원안의 "실제 데이터가 캘린더에 뜨는 것을 가장 먼저 확인" [확정: 원안에서 사용자 동의]을 따른다
- 원안 Cycle 2는 필터(04)와 분류·관리자 확장(05)으로 나눴다

## Cycle 00 foundation

- 목표: 빈 화면이라도 AWS에 배포되어 접속되는 상태
- 범위
  - 저장소, Gradle 골격, Spring Modulith 모듈 경계 검사 [확정: Spring Modulith]
  - PostgreSQL + Liquibase [확정]
  - React 프로젝트, S3 + CloudFront + EC2 배포, CI/CD
- 완료 기준: 내 도메인으로 접속하면 React 화면이 뜨고 `/api/health`가 응답
- 시작 전 확인 필요: Group ID·base package, 도메인, DB 위치(EC2/RDS), CI/CD 도구
- 메모 [안]: 배포까지 넣으면 큰 편이다. `/cycle-start`에서 "로컬 골격"과 "AWS 배포"를 00a/00b로 나눌지 정한다

## Cycle 01 first-source-calendar

- 목표: 실제 전시 데이터가 매일 쌓이고 캘린더에서 바로 보임
- 범위
  - 서울 문화행사 API 어댑터 하나 (조사된 곳 중 공공 API이고 호출이 확인된 곳, `IS_FREE`·`GUNAME` 포함)
  - SourceRecord 저장 → 정규화 → Event·EventPeriod(실제 기간)·Venue
  - collector embedded 모드, 하루 1회
  - 간단한 캘린더: 월 보기에 시작일·종료일만. 필터 없음
- 넣지 않는 것: 관리자 화면, 중복 묶기, 다른 출처
- 완료 기준: 하루 1회 자동 수집되고, 수집한 전시가 월 캘린더에 표시됨
- 시작 전 확인 필요: 서울 API 정식 인증키 발급, API 필드 재확인(6.5 절차), 이 단계에서 검수 없이 바로 반영해도 되는지

## Cycle 02 admin-review-basic

- 목표: 요구사항 3.9 검수 모드가 동작
- 범위
  - 관리자 로그인(관리자 계정 하나)
  - 확인 대기 목록: 승인, 수정 후 승인, 반려
  - 검수 모드 설정: 이상한 것만(기본) / 전부 [확정]
  - "이상한 것" 기준은 기간 이상치부터(종료일 < 시작일, 시작일이 너무 오래됨)
  - 자동 처리 기록
- 완료 기준: 모드별로 수집 결과가 바로 반영되거나 확인 대기로 감
- 시작 전 확인 필요: 기준값 처음 값, 회원 기능 여부(관리자 로그인과 별개)

## Cycle 03 second-source-dedup

- 목표: 출처가 여러 개여도 같은 전시가 하나로 보임
- 범위
  - 예술의전당 어댑터(내부 JSON), 문체부 12개 기관 전시정보 API 어댑터
  - TicketOffer(판매처별 가격·예매 URL)
  - 같은 전시 판별 1~4단계, 애매한 건은 Cycle 02의 확인 대기 목록으로
  - 관리자 "같은 전시 판별" 화면(합치기/나누기, 판정 저장)
- 완료 기준: 같은 전시가 여러 출처에서 와도 캘린더에 하나로 표시됨
- 시작 전 확인 필요: 두 출처 재조사, 판별 기준값(샘플 쌍으로)

## Cycle 04 calendar-filters

- 범위: 지역 필터(기본 전국), 가격 필터(무료 포함), 예매처 구분 표시
- 완료 기준: 필터를 바꾸면 캘린더 결과가 바뀜
- 시작 전 확인 필요: 지역 단위, 가격 구간, 캘린더 보기 종류

## Cycle 05 classification

- 범위: 분류 태깅 1차(키워드 규칙), 분류 체크박스(인기 먼저, 더보기, 첫 화면 3개 선택), 관리자 분류 관리·수동 지정, 관리자 대시보드, 전시 편집·직접 입력
- 시작 전 확인 필요: 분류 목록, 인기 기준, 기본 선택 3개

## Cycle 06 이후 (거칠게)

- 06 earlybird: 얼리버드 차수·기간 수집, 캘린더 탭 전환, NOL·카카오톡 예약하기 등 약관 확인 후 가능한 곳, 이미지 속 텍스트, 네이버 활용 방안, 새 전시 후보·출처 관리 화면. 크면 나눈다
